## Featured project: Aptoria

**Aptoria** is my self-hosted API QA evidence, coverage and release-decision platform.

It is built for practical QA work around API projects, including project-based test organization, endpoint inventory, evidence capture, imported QA artifacts, findings, release gates, decision packages, report exports, and operational QA documentation.

The goal of Aptoria is to provide a lightweight, practical and transparent tool for API quality work, especially for smaller teams, freelancers, portfolio demonstrations, and self-hosted QA workflows.

### Aptoria covers

| Capability | Purpose |
| --- | --- |
| API QA project management | Organize API QA work by project and release context |
| Endpoint inventory | Track release-scope API endpoints |
| Evidence repository | Store checksum-backed QA evidence |
| Import adapter layer | Normalize artifacts from tools such as Postman, Newman, Jira, OpenAPI, CSV and HAR-style inputs |
| Findings workflow | Document issues, risks and release blockers |
| QA Cockpit | Review coverage, blind spots and release confidence |
| Release gates | Turn QA state into a reviewable go/no-go decision |
| Decision packages | Export structured evidence for review and handoff |
| Windows/XAMPP support | Keep local self-hosted deployment practical and reproducible |
| GitHub QA gate | Support public hygiene and repository quality checks |

Repository: [`Szujo-Janos/Aptoria`](https://github.com/Szujo-Janos/Aptoria)
